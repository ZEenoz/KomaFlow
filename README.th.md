## ภาพรวม

KomaFlow คือ **ส่วนขยาย Chrome/Chromium แบบ Manifest V3 สำหรับแปลมังงะและคอมมิกที่ประมวลผลในเครื่องเป็นหลัก (100% local-first) และเร่งความเร็วด้วย WebGPU** ตัวส่วนขยายจะค้นหาข้อความบนหน้า ลบตัวอักษรต้นฉบับ แปลบทสนทนา แล้วจัดวางข้อความกลับลงในภาพ โดยไม่ต้องอัปโหลดหน้าภาพออกไปที่ใด

ไปป์ไลน์ภาพถูกออกแบบให้ทำงานในเครื่องเป็นหลัก:

- **OCR, inpainting, การจัดวางตัวอักษร และการลงสีแบบเลือกได้ ทำงานบนอุปกรณ์ของคุณ** หน้าภาพ พาเนล และภาพที่แปลแล้วจะไม่ถูกอัปโหลด
- **การแปลก็ทำงานในเครื่องได้เช่นกัน** ด้วย WebLLM บน WebGPU หากเลือกเอนจินคลาวด์ KomaFlow จะส่งข้อความที่สกัดได้พร้อมการตั้งค่าการแปลที่จำเป็นสำหรับคำขอนั้น โดยภาพจะไม่ออกจากเบราว์เซอร์
- **ไม่มี telemetry, SDK วิเคราะห์การใช้งาน หรือ tracking pixel** การตั้งค่าและ API key เก็บอยู่ในพื้นที่เก็บข้อมูลของเบราว์เซอร์
- **โมเดลจะถูกดาวน์โหลดเมื่อต้องใช้และแคชไว้ในเครื่อง** ไม่จำเป็นต้องส่งประวัติการอ่านหรือข้อมูลส่วนตัวเพื่อใช้งานส่วนขยาย

KomaFlow รองรับภาษาต้นทางอย่างญี่ปุ่น จีน เกาหลี และภาษาอื่น ๆ โดยมีภาษาเป้าหมายมากกว่า 50 ภาษา รวมถึงอังกฤษ ไทย เวียดนาม และอินโดนีเซีย ใช้ได้กับหน้ามังงะทั่วไป เว็บตูนแบบยาวต่อเนื่อง แกลเลอรีภาพ Pixiv, X/Twitter และเว็บอ่านการ์ตูนที่ต้องกำหนด image selector เอง

## มีอะไรใหม่ใน KomaFlow

KomaFlow ต่อยอดจาก Kites v1.5.2 โดยเพิ่มชุดการแก้ไขและงาน UI ที่เจาะจง หัวข้อต่อไปนี้คือสิ่งที่กระทบการอ่านจริงมากที่สุด

### 1. ฟอนต์ที่นำเข้าและเว็บฟอนต์กำหนดเองเรนเดอร์ได้เสถียร

- **ลงทะเบียนใน offscreen document ที่ทำงานต่อเนื่อง** ซึ่งเป็นบริบทที่เป็นเจ้าของ canvas สำหรับเรนเดอร์ ไม่ใช่ป๊อปอัปหรือ content frame ที่อายุสั้น ฟอนต์ที่นำเข้าและฟอนต์ที่ดาวน์โหลดจากแคตตาล็อกจะถูกลงทะเบียนผ่าน `FontFace` API และ `document.fonts` ในบริบทที่วัดและวาดข้อความจริง
- **ฟอนต์ที่บันทึกไว้จะถูกลงทะเบียนใหม่เมื่อ offscreen document บูต** การรีสตาร์ตเบราว์เซอร์ การรีไซเคิล service worker หรือการเปิดตัวอ่านรอบใหม่ จึงไม่ทำให้ข้อความถูกวัดด้วยฟอนต์สำรองอีกต่อไป
- **ตรวจสอบไฟล์ก่อนบันทึก** ไฟล์ฟอนต์ต้องผ่าน `FontFace.load()` ฟอนต์จากแคตตาล็อกถูกตรวจกับค่า SHA-256 ที่ปักหมุดไว้ และชื่อ family ถูกทำความสะอาด ไฟล์เสียจะถูกปฏิเสธแทนที่จะกลายเป็นตัวเลือกที่ใช้งานไม่ได้
- **คง font stack ทั้งชุดไว้ตามต้นฉบับ** ก่อนหน้านี้ renderer นำ stack ที่มีเครื่องหมายคำพูดอยู่แล้วไปครอบด้วยเครื่องหมายคำพูดอีกชั้น ทำให้ CSS ไม่ถูกต้อง ตัวอย่างเช่น การอ้างทั้งค่า `"CC Wild Words", sans-serif` เป็นชื่อ family เดียว Chrome จะเพิกเฉยต่อ `ctx.font` ที่ผิดรูปแบบและใช้ค่า metric เดิม เช่น `10px sans-serif` ทำให้การวัดขนาด glyph ไม่ตรงกับสิ่งที่วาดจริง ตอนนี้ KomaFlow ส่ง stack ที่สมบูรณ์ให้ทั้ง CSS และ Canvas ทำให้การคำนวณขนาด การตัดบรรทัด การ fit คอนทัวร์ และเส้นขอบใน Studio ตรงกัน

การแก้ไขนี้ครอบคลุมตัวเลือกฟอนต์ในป๊อปอัปและ KomaFlow Studio รวมถึงการเปิดครั้งแรก การสลับฟอนต์ การแปลซ้ำบนหน้าเดิม และฟอนต์ที่นำเข้าและใช้หลายหน้า

### 2. ตัวเลือกการเรนเดอร์ข้อความครบชุด

ป๊อปอัปมีตัวควบคุมการจัดตัวอักษรที่ใช้กับทุกเส้นทางการจัดวาง ไม่ใช่แค่เอนจินเดียว:

| ตัวเลือก | ช่วงค่า | การทำงาน |
| :--- | :--- | :--- |
| **Bold** | เปิด / ปิด | ใช้ฟอนต์หน้าหนา (bold face) ของ family ที่เลือก พร้อมค่า metric ที่สอดคล้องกัน |
| **Italic** | เปิด / ปิด | ใช้ฟอนต์หน้าเอียง (italic face) และคงกฎการ fit และการจัดแนวเดิมไว้ |
| **Min Font Size** | 4–20 px ค่าเริ่มต้น 6 px | **ค่าต่ำสุดแบบบังคับหลังการ fit** ไม่ใช่ขนาดเริ่มต้น ขนาดสุดท้ายจะไม่ต่ำกว่าค่านี้ |
| **Text Alignment** | Auto / Left / Center / Right | Auto คงการจัดแนวตามเลย์เอาต์ต้นฉบับ ส่วนตัวเลือกอื่นใช้กับการจัดวางที่ fit แล้วอย่างสม่ำเสมอ |
| **Disable Stroke** | เปิด / ปิด | ลบเส้นขอบแต่ยังคงสีเติมที่ปรับตามพื้นหลัง เพื่อให้อ่านข้อความได้ชัด |

ค่าต่ำสุดถูกบังคับใช้ในเส้นทาง **Contour**, **Simple Rect**, **AutoBalloon**, renderer แบบ **Legacy** และการจัดวางข้อความใน **Studio OCR** เมื่อเปลี่ยนตัวเลือกการเรนเดอร์ใด ๆ ลายเซ็นการตั้งค่าจะเปลี่ยน และระบบจะไม่นำเลย์เอาต์ที่แคชจากค่าเดิมมาใช้ในการแปลครั้งถัดไป

### 3. ตัวสแกนหน้าและ Chapter Reader ที่เชื่อถือได้ขึ้น

ตัวสแกนของตัวอ่านถูกเสริมความทนทานโดยอิงปัญหาที่พบบ่อยบนเว็บมังงะจริง:

- **ปรับ URL ให้เป็นรูปแบบ canonical** ตัดพารามิเตอร์ที่เปลี่ยนตลอดอย่าง cache-busting, tracking (`utm_*`, `x-amz-*`) และ hash ออก แต่ยังคงพารามิเตอร์การแบ่งหน้าและ image proxy ไว้พร้อมจัดเรียง หน้าภาพเดียวกันที่เสิร์ฟด้วยพารามิเตอร์แคชหรือ tracking ที่เปลี่ยนไปจะถูกมองเป็นหน้าเดียว ไม่ซ้ำ
- **ค้นหาภาพแบบ lazy-load ได้กว้างขึ้น** KomaFlow กระตุ้นแอตทริบิวต์ `data-src` / `data-original` / `data-lazy-src`, `data-srcset` และ `loading="eager"` ยอมรับภาพที่ยังมีขนาด 0×0 หรือยังวัดขนาดไม่ได้ และยังกรองอวตาร โลโก้ โฆษณา และภาพปกแนะนำออก
- **พรีโหลดด้วย fast scroll ที่ครอบคลุมขึ้น** เลื่อนได้สูงสุด **180 รอบต่อเป้าหมายการเลื่อน** (หน้าและ scroll container ภายในอาจรวมกันได้ถึง 360 รอบ) ภายในเวลาจำกัด 6 วินาที เพื่อบังคับให้หน้าแบบ lazy โหลดก่อนสร้างรายการบท แล้วคืนตำแหน่งเลื่อนเดิม
- **รีเซ็ตบริบทเมื่อนำทางแบบ SPA** เหตุการณ์ `popstate`, `hashchange` และการเปลี่ยน URL จะรีเซ็ตบริบทของบท เพื่อไม่ให้เส้นทางใหม่รวมรายการภาพของบทเก่า
- **อัปเดตสดขณะเปิดตัวอ่าน** ใช้ `MutationObserver` ร่วมกับเหตุการณ์ `load` ของภาพ เพื่อเพิ่มหน้าที่ปรากฏหลังการสแกนแรก โดยไม่ทำให้ตัวอ่านค้างหรือสแกนทั้งเอกสารใหม่ทุกครั้งที่มีการเปลี่ยนแปลง
- **ปุ่ม Rescan บนแถบหัว** กดครั้งเดียวเพื่อกระตุ้น lazy attribute รัน fast preload ใหม่ และรีเฟรชรายการหน้าโดยไม่ต้องปิดตัวอ่าน
- **ล้างแคชเมื่อการตั้งค่าการเรนเดอร์เปลี่ยน** เมื่อเปลี่ยนตัวเลือกการจัดตัวอักษร content script จะเพิ่มเวอร์ชันของการตั้งค่าและทิ้งผลลัพธ์ที่แคชไว้ เพื่อไม่ให้แสดงหน้าที่เรนเดอร์ด้วยฟอนต์ชุดเก่า

> _ภาพหน้าจอใน README นี้ถ่ายไว้ก่อนการย้ายธีม KomaFlow และยังแสดง UI ของ Kites ต้นทางอยู่ ภาพชุดใหม่ถูกติดตามเป็นงานต่อเนื่อง ส่วนตัวส่วนขยายที่ติดตั้งจริงใช้ธีมตามที่อธิบายไว้ข้างต้นแล้ว_

## ภาพรวมฟีเจอร์

### โหมดแปลในตำแหน่งเดิม

KomaFlow ซ้อนภาพที่แปลแล้วลงบนเว็บที่คุณอ่านโดยตรง เลือกโหมดที่เข้ากับวิธีอ่านของคุณ:

| โหมด | การทำงาน | เหมาะกับ |
| :--- | :--- | :--- |
| **Hover** | ป้ายลอยเล็ก ๆ ปรากฏบนภาพการ์ตูน คลิกเพื่อแปลตรงตำแหน่ง | แปลเป็นครั้งคราวขณะเลื่อนฟีดและแกลเลอรี |
| **Persistent** | ป้ายแปลแสดงอยู่บนภาพที่ตรวจพบทุกภาพ | หน้าที่ต้องการปุ่มแปลชัดเจนบนทุกช่อง |
| **Auto-Translate** | ช่องภาพใหม่ถูกจัดคิวอัตโนมัติเมื่อเข้ามาใน viewport ระหว่างเลื่อนหน้า | บทยาวและฟีดที่มีภาพจำนวนมาก |
| **Screen Crop** | ลากเลือกพื้นที่หน้าจอ รวมถึง canvas ที่ถูกป้องกัน, WebGL หรือวิดีโอ แล้วแปลเฉพาะพื้นที่นั้น | เกม ตัวอ่านแบบ canvas และเว็บที่อ่านภาพโดยตรงไม่ได้ |
| **คลิกขวา** | ใช้เมนูบริบทของเบราว์เซอร์บนภาพใด ๆ แล้วเลือกคำสั่ง KomaFlow | ภาพครั้งเดียวและเว็บที่มีโครงสร้างผิดปกติ |

Screen Crop เลือกพื้นที่เดิมซ้ำได้ด้วยคีย์ลัด เหมาะกับเกมวิชวลโนเวลและหน้าที่เรนเดอร์เฟรมเดิมซ้ำ ภาพที่แปลแล้วรองรับ **hold-to-peek**: แตะ `F` เพื่อสลับไปดูต้นฉบับและคงไว้ หรือกดค้างเกิน 200 ms แล้วปล่อยเพื่อกลับมาที่ภาพแปลทันที

[![ป้ายแปลแบบ hover ของ KomaFlow บนช่องมังงะ](./README_images/UI-feature/hover-inplace-preview.png)](./README_images/UI-feature/hover-inplace-preview.png)

### คีย์ลัด

| การทำงาน | คีย์ลัด | ขอบเขต |
| :--- | :--- | :--- |
| แปลภาพใต้ตัวชี้ | `Alt+Shift+Z` (`Ctrl+Shift+Z` บน macOS) | หน้าเว็บ |
| เริ่มเลือกพื้นที่หน้าจอ | `Alt+Shift+X` (`Ctrl+Shift+X` บน macOS) | หน้าเว็บ |
| ทำ Screen Crop เดิมซ้ำ | `Alt+Shift+C` (`Ctrl+Shift+C` บน macOS) | หน้าเว็บ |
| เปิด Chapter Reader | `Alt+Shift+M` (`Ctrl+Shift+M` บน macOS) | หน้าเว็บ |
| สลับหรือกดค้างดูต้นฉบับ | `F` | หน้าเว็บ เฉพาะภาพที่ hover และแปลแล้ว |

| สลับหน้าต้นฉบับ | `F` | ตัวอ่าน |

หากคีย์ลัดชนกับเว็บหรือส่วนขยายอื่น คำสั่งของ Chrome เปลี่ยนได้ที่ `chrome://extensions/shortcuts` แต่ปุ่มแปล, ครอป และตัวอ่านที่จัดการในหน้าเว็บจะยังคงใช้คีย์ชุดนี้แม้เปลี่ยนคำสั่งของ Chrome แล้ว และการยกเลิกผูกคำสั่งของ Chrome จะไม่ปลดคีย์ในหน้าเว็บ

### Chapter Reader และการส่งออก ZIP

Chapter Reader รวมบทมังงะที่แบ่งหน้าไว้ในมุมอ่านต่อเนื่องเพียงหน้าเดียว

[![Chapter Reader ของ KomaFlow ที่เปิดบทอยู่](./README_images/UI-feature/reader.jpg)](./README_images/UI-feature/reader.png)

- **Fast Scan** เดินหน้าผ่านตัวพรีโหลดแบบ lazy แล้วสร้างรายการหน้าที่ไม่ซ้ำและเรียงตามตำแหน่งบนหน้า
- **โหมดเว็บตูน หน้าเดียว และหน้าคู่** รองรับแถบยาวต่อเนื่อง หน้ามังงะมาตรฐาน และหน้าคู่
- **รองรับการอ่านจากขวาไปซ้ายและจากซ้ายไปขวา** โดยปุ่มลูกศรจะทำตามทิศทางที่เลือก
- **วนความกว้างเว็บตูน** ระหว่างขนาดกลาง ใหญ่ และเต็มความกว้างด้วย `W`
- **แปลทั้งบทแบบกลุ่ม** แปลทุกหน้าที่ตรวจพบในครั้งเดียวพร้อมความคืบหน้าและสถานะข้อผิดพลาดรายหน้า
- **ส่งออก ZIP ในคลิกเดียว** รวมภาพที่แปลเป็น `<chapter-title>-translated.zip` สำหรับอ่านออฟไลน์ ไฟล์เก็บแบบ STORE (ไม่บีบอัด) และบทต้องมีขนาดไม่เกิน 256 MiB กับจำนวนรายการไม่เกิน 65,535
- **ปุ่ม Rescan บนแถบหัว** รีเฟรชรายการหน้าเมื่อเว็บโหลดหน้าเพิ่มหลังเปิดตัวอ่าน
- **ไม่อัปโหลดขึ้นเซิร์ฟเวอร์** ไฟล์ ZIP ถูกประกอบในเบราว์เซอร์และบันทึกผ่านการดาวน์โหลดปกติ

### KomaFlow Studio ในตัว

KomaFlow Studio คือตัวแก้ไขเต็มจอสำหรับแก้คำแปล ปรับการจัดตัวอักษร หรือเก็บรายละเอียดภาพด้วยมือ เปิดได้จากปุ่ม Studio ในป๊อปอัป ซึ่งจะเปิด Studio ในแท็บใหม่

[![KomaFlow Studio กำลังแก้ไขหน้ามังงะที่แปลแล้ว](./README_images/UI-feature/kite_studio_editing.jpg)](./README_images/UI-feature/studio-editor.png)

- **แก้ไขในที่:** ดับเบิลคลิกฟองคำพูดแล้วแก้ข้อความได้ทันที พร้อมจัดวางใหม่และจัดกึ่งกลางแนวตั้งแบบสด
- **canvas แบบอินเทอร์แอกทีฟ:** ย้ายและปรับขนาดฟองคำพูดด้วยจุดจับ 8 จุด และปรับพื้นที่ข้อความแยกได้
- **แปรง inpaint:** ลบตัวอักษรที่เหลือ SFX หรือตำหนิบนภาพได้ในเครื่อง ด้วยฝีแปรงที่ปรับขนาดได้
- **ตรวจสอบแบบเทียบเคียง:** เปรียบเทียบภาพต้นฉบับ ภาพที่ลบข้อความแล้ว และผลลัพธ์ที่จัดวางข้อความแล้ว
- **ควบคุมการจัดตัวอักษร:** family, ขนาด, สี, การจัดแนว, ระยะบรรทัด, bold, italic, stroke และขนาดขั้นต่ำ
- **Studio OCR:** นำเข้าหน้าภาพแล้วรัน OCR พร้อมจัดวางข้อความภายในตัวแก้ไข
- **ส่งออก:** บันทึกหน้าที่แปลแล้วที่ความละเอียดต้นฉบับ หรือส่งออกโปรเจกต์ไว้แก้ไขต่อ

### คลังคำศัพท์เฉพาะและกฎโดเมน

- **Custom Glossary:** กำหนดชื่อตัวละคร คำเรียกขาน และศัพท์เฉพาะให้แปลตามที่ต้องการ รายการที่ตรงกับข้อความจะถูกใส่ใน prompt ของ WebLLM, Cloud Shared Pool และ Custom API แบบ LLM โดยใส่เฉพาะคำที่เกี่ยวกับชุดข้อความปัจจุบัน Google Translate ไม่ได้ใช้รายการ glossary และหากเลือกเอนจินคลาวด์ ข้อความ glossary จะถูกส่งไปยังผู้ให้บริการนั้นด้วย จึงไม่ควรใส่ข้อมูลอ่อนไหว

## เอนจิน AI และไปป์ไลน์

### ไปป์ไลน์โดยสรุป

| ขั้นตอน | สิ่งที่เกิดขึ้น | รันที่ไหน |
| :--- | :--- | :--- |
| 1. ค้นหา | หาภาพการ์ตูน ช่องภาพ และหน้าบท กระตุ้นแหล่งภาพแบบ lazy และกรองสิ่งรบกวนของ UI | Content script ในเครื่อง |
| 2. OCR | ตรวจจับและอ่านบทสนทนาด้วย PaddleOCR โดยแบ่งภาพแถบยาวแบบ 1 มิติ | Offscreen document บน WebGPU หรือ WASM |
| 3. จัดกลุ่ม | รวมบรรทัดข้อความที่อยู่ติดกัน กรอง furigana และ noise แล้วเรียงลำดับการอ่าน | ในเครื่อง |
| 4. Inpainting | ลบตัวอักษรต้นฉบับและสร้างพื้นหลังใต้ตัวอักษรขึ้นใหม่ | Offscreen document ด้วย ONNX Runtime Web |
| 5. แปล | แปลบทสนทนาที่จัดกลุ่มแล้วด้วยเอนจินที่เลือก glossary และเชนสำรอง | WebLLM ในเครื่องหรือผู้ให้บริการคลาวด์ |
| 6. จัดวางข้อความ | fit ข้อความให้พอดีฟองคำพูดหรือพื้นที่ caption ตัดบรรทัด และวาด glyph สุดท้าย | Canvas pipeline ในเครื่อง |
| 7. ลงสี | ลงสีหน้าภาพที่ลบข้อความแล้วด้วย AI แบบเลือกได้ | Offscreen document ด้วย ONNX Runtime Web |

### ภาพรวมเอนจิน

| องค์ประกอบ | ตัวเลือก | การทำงาน | หมายเหตุ |
| :--- | :--- | :--- | :--- |
| **Translation** | **Google Translate** (ค่าเริ่มต้น), **Cloud Shared Pool**, **WebLLM**, **Custom API** | ในเครื่องหรือคลาวด์ตามเอนจิน | เฉพาะบทสนทนาที่สกัดได้และการตั้งค่าคำขอที่กำหนดไว้เท่านั้นที่ออกจากเบราว์เซอร์ และเฉพาะเอนจินคลาวด์ ไม่มีการส่งภาพ |
| **Inpainting** | None (Bypass), Simple Fill, Precise Fill, Telea Diffusion, LaMa Manga, AOT-GAN | ในเครื่อง | วิธี built-in 4 แบบและโมเดล neural 2 ตัว (~50 MB และ ~60 MB) |
| **OCR** | PaddleOCR 10 พรีเซ็ต: v6-small (ค่าเริ่มต้น), v6-medium, v6-tiny, v5-mobile, v5-server, v5-en-mobile, v4-mobile, v4-server, v3-mobile, v3-japanese-mobile | ในเครื่อง | ใช้ WebGPU และถอยไปใช้ WASM ได้ พร้อมแบ่งภาพแบบ 1 มิติสำหรับเว็บตูนที่สูงมาก |
| **Bubble Fit** | Disabled, Heuristic, YOLO (AI) | ในเครื่อง | โหมดจริงคือ `off`, `heuristic` และ `neural` ส่วน MST เป็นเรขาคณิตภายในขั้นตอนจัดกลุ่ม ไม่ใช่โหมดที่เลือกได้เป็นตัวที่สาม YOLO ใช้โมเดลเพิ่ม ~11 MB |
| **Color-Bubble** | ตรวจจับสีข้อความรายฟอง + จับคู่สีฟอนต์ + wrap ในฟอง; Manga Colorizer แบบเลือกได้ | ในเครื่อง | การตรวจจับสีข้อความใช้ canvas/K-Means ส่วน colorizer SEResNeXt U-Net แบบเลือกได้ใช้ ~61 MB |

### เอนจินการแปล

- **Google Translate (`gg-translate`, ค่าเริ่มต้น):** ใช้ปลายทาง GTX สาธารณะโดยไม่ต้องใช้ API key คำขอถูกแบ่งชุดด้วยเพดาน 1,800 ตัวอักษรและหมดเวลาแต่ละครั้งที่ 8 วินาที สะดวกและไม่มีค่าใช้จ่าย แต่เป็นปลายทางที่ไม่เป็นทางการ ความพร้อมใช้งาน อัตราจำกัด และคุณภาพผลลัพธ์ขึ้นอยู่กับ Google ไม่ใช่ KomaFlow
- **Cloud Shared Pool:** บริการ Cloudflare Worker พร้อม Google OAuth แบบเลือกได้ โควตาคือ **แปลสำเร็จ 100 ครั้งในหน้าต่าง 24 ชั่วโมงที่นับจากครั้งแรกที่คุณแปล** (หน้าต่างไม่เลื่อนตามแต่ละคำขอ), **จำนวนครั้งที่พยายาม 250 ครั้งต่อวัน** และเพดานรับคำขอรวมทั้งระบบ **10,000 ครั้งต่อวัน** เหมาะกับการใช้เป็นครั้งคราวและอาจส่งต่อไปยังโมเดลที่ชุมชนโฮสต์ไว้
- **WebLLM:** รันโมเดลแปลแบบ open-weight ในเครื่องบน WebGPU รายการโมเดลที่มาพร้อมส่วนขยายมี **59 โมเดล** จากตระกูล Qwen 3.5/3/2.5/2, Gemma 2/3/4, Llama 3.1/3.2, Phi-3.5/4, Mistral/Ministral และ LFM2.5 ดาวน์โหลดโมเดลครั้งเดียวแล้วใช้งานออฟไลน์ได้ ขึ้นกับหน่วยความจำ GPU และ context window ของโมเดล
- **Custom API:** รองรับผู้ให้บริการ `openai`, `openai-compatible`, `gemini` และ `claude` โดย `openai-compatible` ครอบคลุม Ollama, vLLM, LM Studio และปลายทางที่คล้ายกันในเครื่อง API key และ endpoint เก็บในพื้นที่เก็บข้อมูลของส่วนขยาย และคำขอส่งตรงไปยังผู้ให้บริการที่คุณตั้งค่า

เชนเอนจินสำรอง (fallback chain) ปรับได้และว่างเปล่าโดยค่าเริ่มต้น หากเอนจินที่เลือกทำงานล้มเหลว KomaFlow จะไม่เปลี่ยนเส้นทางเงียบ ๆ เว้นแต่คุณจะเพิ่มเอนจินสำรองในการตั้งค่า

### ตัวเลือก Inpainting

| ID | ชื่อที่แสดง | แท็ก | โมเดล |
| :--- | :--- | :--- | :--- |
| `none` | None (Bypass) | Raw Canvas | Built-in |
| `simple` | Simple Fill | Fast Color | Built-in |
| `stroke-fill` | Precise Fill | Text Stroke | Built-in |
| `telea` | Telea Diffusion | Fast Diffusion | Built-in |
| `lama-manga` | LaMa Manga | Neural Dynamic | ~50 MB |
| `aotgan` | AOT-GAN | Neural High-Detail | ~60 MB |

### หมายเหตุด้านประสิทธิภาพ

- **แนะนำ WebGPU** สำหรับ OCR, WebLLM และ inpainting แบบ neural PaddleOCR และตัวรัน inpainting ถอยไปใช้ WASM/CPU ได้ แต่จะช้ากว่า
- **การใช้ครั้งแรกจะดาวน์โหลดโมเดล** LaMa, AOT-GAN, YOLO สำหรับตรวจจับฟองคำพูด, colorizer และน้ำหนัก WebLLM จะถูกแคชในเครื่องหลังดาวน์โหลด
- **หน้าแบบแถบยาว** ถูกประมวลผลด้วยการแบ่ง canvas แบบ 1 มิติในหน่วยความจำ ความสูงเว็บตูนที่มากผิดปกติจึงไม่ถูกย่อลงเงียบ ๆ จนติดขีดจำกัด texture ของ GPU
- **คุณภาพขึ้นกับต้นฉบับ** ตัวอักษรเล็กหรือความละเอียดต่ำ การสแกนที่มี noise ฟอนต์แปลก และ SFX ที่ซับซ้อนเป็นงานยากสำหรับ OCR และ inpainting ส่วน Studio มีไว้สำหรับหน้าที่ต้องเก็บรายละเอียดด้วยมือ

## การติดตั้ง

### สิ่งที่ต้องมี

- **Chrome, Chromium, Edge, Brave หรือเบราว์เซอร์ Chromium อื่น** ที่รองรับ Manifest V3
- **WebGPU** สำหรับการแปลด้วย LLM ในเครื่องและเอนจินประสาท เปิด hardware acceleration ในเบราว์เซอร์ และตรวจว่า `chrome://gpu/` รายงาน WebGPU เป็น hardware accelerated
- **Node.js 22.14** (ปักหมุดใน `.nvmrc`) และ **npm 10+** เฉพาะกรณีสร้างจากซอร์สโค้ด

### ทางเลือกที่ 1: ไฟล์ ZIP จากรีลีส

1. เปิด **[หน้ารีลีสของ KomaFlow](https://github.com/ZEenoz/KomaFlow/releases/latest)**
2. ดาวน์โหลดไฟล์ `.zip` รีลีสล่าสุด
3. แตกไฟล์ไว้ในโฟลเดอร์ถาวร อย่าลบหรือย้ายโฟลเดอร์หลังโหลดส่วนขยายแล้ว
4. เปิด `chrome://extensions/`
5. เปิด **Developer mode** ที่มุมขวาบน
6. คลิก **Load unpacked** แล้วเลือกโฟลเดอร์ที่แตกไฟล์ไว้
7. ปักหมุด **KomaFlow** ไว้บน toolbar แล้วเปิดป๊อปอัป

หากหน้ารีลีสยังไม่มีไฟล์ให้ดาวน์โหลด ให้ใช้ทางเลือกที่ 2 การโหลดโฟลเดอร์ `dist/` ในเครื่องใช้กลไกการติดตั้งเดียวกัน

### ทางเลือกที่ 2: สร้างจากซอร์สโค้ด

```bash
# 1. โคลนรีโป
git clone https://github.com/ZEenoz/KomaFlow.git
cd KomaFlow

# 2. ติดตั้ง dependency ตาม lockfile
npm ci

# 3. คัดลอก WASM, ตรวจชนิดข้อมูล และ build ส่วนขยาย
npm run build
```

จากนั้น:

1. เปิด `chrome://extensions/`
2. เปิด **Developer mode**
3. คลิก **Load unpacked** แล้วเลือกโฟลเดอร์ `dist/` ที่สร้างขึ้น
4. ปักหมุด **KomaFlow** และกดรีโหลดส่วนขยายหลัง build ใหม่

ขั้นตอน build จะคัดลอกไฟล์ ONNX Runtime WASM รัน TypeScript project build และบันเดิลป๊อปอัป content script, offscreen document และ Studio ผ่าน Vite

## ความเป็นส่วนตัวและการไหลของข้อมูล

KomaFlow ใช้รูปแบบข้อมูลแบบ local-first:

1. **ภาพประกอบอยู่ในเครื่อง** content script และ offscreen document อ่านพิกเซลในหน่วยความจำ ภาพที่แปลแล้วและภาพพื้นหลังที่ลบข้อความแล้ว (clean plate) ของ Studio เก็บใน IndexedDB ของเบราว์เซอร์ ไม่ได้อัปโหลด
2. **OCR และ inpainting ทำงานในเครื่อง** PaddleOCR, LaMa, AOT-GAN, Telea และ canvas สำหรับจัดวางข้อความไม่ส่งข้อมูลภาพผ่านเครือข่าย
3. **การแปลเป็นขั้นตอนเดียวที่อาจใช้เครือข่าย** Google Translate, Cloud Shared Pool และ Custom API จะได้รับข้อความบทสนทนาที่สกัดแล้ว พร้อมการตั้งค่า glossary หรือ custom prompt เมื่อเปิดใช้ ส่วน WebLLM และปลายทาง OpenAI-compatible ในเครื่องเก็บข้อความไว้บนเครื่องคุณเช่นกัน
4. **OAuth เป็นทางเลือก** เฉพาะ Cloud Shared Pool ที่ต้องลงชื่อด้วย Google โดย KomaFlow ได้รับรหัสบัญชี อีเมล และชื่อที่จำเป็นสำหรับการจำกัดโควตา ไม่ต้องใช้บัญชี Google กับ Google Translate, WebLLM หรือ Custom API
5. **การตั้งค่าและคีย์อยู่ในเครื่อง** API key อยู่ใน `chrome.storage.local` และกำหนดระยะเก็บประวัติได้ (1 วัน, 1 สัปดาห์, 1 เดือน หรือไม่เก็บเลย ค่าเริ่มต้นคือ 1 สัปดาห์)
6. **ไม่มี analytics** ส่วนขยายไม่มี SDK วิเคราะห์การใช้งาน tracking pixel หรือ diagnostic beacon

นโยบายฉบับละเอียดอยู่ใน [PRIVACY.md](PRIVACY.md) หากเลือกผู้ให้บริการแปลบนคลาวด์ ข้อกำหนดความเป็นส่วนตัวของผู้ให้บริการนั้นจะมีผลกับข้อความที่ส่งไป

## โครงสร้างโปรเจกต์

```text
src/
  background/     service worker ของ MV3, การส่งข้อความ, การ normalize state
  content/        ตัวสแกนหน้า, โอเวอร์เลย์, ตัวอ่าน, คีย์ลัด, การส่งออก ZIP
  offscreen/      ไปป์ไลน์และเอนจิน WebGPU/ONNX/WebLLM
  popup/          การตั้งค่า, การเลือกเอนจิน, glossary, กฎโดเมน
  shared/         ชนิดข้อมูล, แคตตาล็อก, storage key, font library, utility
  studio/         ตัวแก้ไขและเครื่องมือ canvas ของ KomaFlow Studio
worker/           Cloudflare Worker สำหรับ Cloud Shared Pool
docs/             สถาปัตยกรรม, ADR, คู่มือพัฒนา, ประวัติการพัฒนา
README_images/    ภาพหน้าจอและภาพเปรียบเทียบที่ใช้ใน README นี้
```

ซอร์สโค้ดของส่วนขยายแยกโมดูลอย่างตั้งใจ: แคตตาล็อกเอนจินมีแหล่งความจริงเดียวใน `src/shared/` offscreen document เป็นเจ้าของวงจรชีวิตของโมเดล และ content script แยกเป็นโมดูล scanner, media target, reader และ shortcut แทนที่จะรวมทุกอย่างไว้ในไฟล์เดียว
